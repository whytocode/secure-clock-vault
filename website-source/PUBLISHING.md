# Website build and publication

This directory contains the website's original source. It is licensed under the
repository's AGPL-3.0-only license. Python 3.9+ is the only build dependency.
No npm packages, external fonts, analytics, backend, or paid hosting are required.
The optional JavaScript regression tests use Node's built-in test runner.

The homepage is a product/help hub: 20 searchable feature cards, app screenshots,
original clock artwork, a sharing comparison, six practical guides, security boundaries,
download-file explanations, FAQs, and source/support resources. Search combines category
and whitespace-separated keywords entirely in memory. Without JavaScript all cards,
native disclosures, guides, and download links remain available.
Generated CSS and JavaScript URLs carry content-derived version parameters so a new
page does not reuse stale cached styling or behavior after an update.

- Public repository: https://github.com/whytocode/secure-clock-vault
- Current release: https://github.com/whytocode/secure-clock-vault/releases/tag/v3.21

The user approved the personal account `whytocode`. The live site uses GitHub Pages
with enforced HTTPS and release assets hosted by GitHub Releases. All three release
assets (APK, source, and signature sidecar) were downloaded without authentication
and verified against their expected sizes and SHA-256 hashes after publication.
No custom domain or paid hosting was purchased.

The public repository has a separate, clean history. This Android checkout's history
and private signing material were not published. Preserve that separation on updates.

## Publishing authorization

Publication requires the user's approval of the public GitHub owner/repository.
Do not infer that a connected work account is approved for personal distribution.
GitHub Enterprise Managed User accounts cannot create public repositories; use the
approved personal account rather than trying to override enterprise restrictions.
Until an owner is approved, build the preview without `--repository`: it explicitly
states that downloads and support are not live, and includes a disallow-all robots file.
The build scripts only generate files; they do not provision GitHub resources.

## Build and review

Use a directory containing the verified canonical APK and matching source archive:

```sh
python3 website/scripts/build.py \
  --artifacts /absolute/path/to/release-files \
  --output build/website-preview

SCV_ARTIFACTS=/absolute/path/to/release-files \
  python3 -m unittest discover -s website/tests -v

node --test website/tests/site.test.cjs
node --check website/assets/site.js

python3 -m http.server 8765 --bind 127.0.0.1 --directory build/website-preview
```

Open `http://127.0.0.1:8765`. Build output must be a new, empty named directory
under `build/`; the builder never deletes an existing output or unrelated files.
The artifact check verifies both file hashes and sizes against `website/release.json`
and checks the source's build configuration, license, and distribution notice.
It copies only the explicitly allowlisted web assets and license files. It never
copies APKs, signing material, source archives, runtime logs, or repository history.

The screenshots are resized synthetic Compose captures, not private user data:
`SecureClockVault-library-dark.png` and `SecureClockVault-media-cards.png`
from 3.19, and `SecureClockVault-group-members.png` from 3.20. The mountain artwork
was generated by this project's test fixtures. The hero's `daylight.png` comes from
the validated daylight fixture in `SecureClockVault-daylight-refresh/previews/library-light.png`;
its application UI code is identical to the signed 3.21 release. It is resized to
600 x 1187 without cropping. The older showcase captures remain labeled separately.
The small clock tile is clearly
labeled illustrative artwork, not a screenshot of the clock app. The larger analog
dial is original CSS artwork and is also explicitly labeled as an illustration.

Before publication, exercise 320px/mobile and desktop layouts, 200% text scaling,
keyboard navigation, help disclosures, privacy navigation, clipboard denial,
reduced motion, no-JavaScript behavior, and the real release links. Exercise combined
category/search filtering, mixed-case multiword searches, no results, and Reset filters
(including restored input focus). Open all disclosures during narrow-screen checks.
Keep content grounded in the matching app release, including temporary video-editing
cache limitations and the distinction between backup and chat recovery.

## Approved public configuration

Once the user approves the owning personal account and public repository, generate
the public configuration:

```sh
python3 website/scripts/build.py \
  --artifacts /absolute/path/to/release-files \
  --repository APPROVED_OWNER/APPROVED_REPOSITORY \
  --output build/website-public
```

This only prepares files; it does not upload or authorize anything. The generated
`release.json` contains the website, APK, source, version, sizes, and checksum data.
Links are pinned to the version's release tag so a cached page does not describe
one APK's checksum while downloading a newer APK through a mutable `latest` URL.
The APK filename remains `SecureClockVault-release.apk`.

1. Create a **new public repository** under the approved account. Do not make the
   current Android worktree/history public or use an employer's account without consent.
2. Put the generated static output at that repository's root. Include the original
   website sources under a separate `website-source/` directory (this directory's
   templates, scripts, tests, images, and publishing guide). Include the app's
   `LICENSE`, `NOTICE`, and the four `app/src/main/assets/licenses/` files under
   `website-source/context/`, preserving their filenames and contents.
   These satisfy the website's source availability separately from the app archive.
   The website source builder expects the Android checkout layout; restore that layout
   using the matching Android archive and place `website-source/` at `website/`.
   Do not upload `build/`, session artifacts, signing credentials, or `.git` history.
3. Create the `v3.21` release and attach the verified canonical APK, its matching
   `.idsig` sidecar, and **`SecureClockVault-3.21-source.zip`**. The latter includes
   the application source/build scripts and all 11 pinned upstream source archives.
   GitHub's automatic website-repository source ZIP is **not** a substitute.
4. Enable GitHub Pages from the public repository's root/main branch. Use the
   provided `github.io` address and enforce HTTPS. Do not register a paid domain.
5. Verify anonymous access to the deployed site, APK, and corresponding source.
   Download both actual assets and compare hashes. Check the APK's existing signing
   certificate with `apksigner`; keep the release key private.
6. Report the actual live URL only after deployment and downloads succeed.

No form, private inbox, private security-reporting channel, store listing, employer
endorsement, certification, or legal sign-off is implied. GitHub issues are public.
Keep hosting privacy and Android installation guidance current.

## Website-only updates

For an existing deployment, clone the approved public distribution repository into a
separate build directory and inspect its current commit for unexpected edits. Generate
fresh public output, update only intended generated files and matching `website-source/`
files, and preserve its README, context/license files, and history. Do not repeat the
initial repository/release creation or publish the Android checkout's history.

Commit and push under the approved owner, then verify that GitHub Pages built that commit
and anonymously served the expected HTML, CSS, JavaScript, and unchanged release links.
Website-only changes do not require a new APK, release tag, or Android source archive.
Never change `release.json` hashes merely to accommodate a website refresh.

## Release upkeep

Keep only the current public release bundle per this project's distribution policy.
Stage and verify replacements before removing superseded assets. Use a new release tag
with the same APK filename, update all website metadata, and verify live links before
retiring old downloads. A cached old page can become stale after retirement; never
silently send it a different APK. Android updates must preserve the signing identity.

The original 3.20 source bundle contained an outdated 3.12.1 header and filename
in `NOTICE`, plus an outdated QR-generation-only description of ZXing (it now also
decodes explicitly scanned Nearby QR codes). `scripts/refresh_notice.py` makes a
strictly bounded correction:

```sh
python3 website/scripts/refresh_notice.py /absolute/path/SecureClockVault-3.20-source.zip
```

It verifies that every other archive entry is byte-identical before replacing the
archive. This changes the source ZIP's hash, not the APK or Android code. Update the
source bytes/hash in `release.json` and retained release validation metadata afterward.
Do not use this helper to substitute modified application code for a signed release.
