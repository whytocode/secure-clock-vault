Details & limits

The app supports up to five password-routed profiles. Each password opens its matching vault, without listing other profiles on the unlock screen. A compromised device may still reveal that multiple profile records exist; this is not guaranteed forensic concealment.

Edits save as a new encrypted copy beside the original. Processing is bounded to a 4096-pixel maximum edge. Redaction is manual, not automatic face or text detection. Image-editing working buffers stay in memory.

Details & limits

Results are new encrypted files. Trims follow platform keyframe boundaries; conversion changes the container, not the codec, and does not bypass DRM. Some editing/conversion operations require temporary app-private plaintext files. Read the storage caveat.

Beyond files

Notes, credentials & TOTP

Details & limits

Document records can reference an imported vault file. Offline TOTP uses six digits and a 30-second period, and depends on an accurate device clock. The app does not perform account enrollment or provide account recovery.

Start here

Your first five minutes

  1. Download the APK below and follow Android's installation prompts.
  2. Open Clock. Draw a deliberate X in two crossing strokes across the launch face.
  3. Create and confirm an alphanumeric vault password of at least eight characters.
  4. Use Add to import a small test file. Reopen it and create a verified backup before relying on the vault.

Keep your originals until you are confident in your import and backup.

Before you need it

Make an encrypted backup

  1. Open Tools and more → Backup and restore.
  2. Choose a destination and a separate backup password of at least ten characters.
  3. Keep the vault open until the written file has been read back and verified.
  4. Keep a trusted copy and test a restore. Store the password separately.

Library backup is not chat recovery: identities, history, pending transfers, other profiles, and clock settings are excluded.

One-to-one

Connect with a friend

  1. Open Private chats, choose a local display name, and review relay conditions.
  2. Exchange a one-time invitation link and keep both vaults open until connected.
  3. Compare security codes through a trusted channel. Respect the conversation's verification requirement.
  4. Select files and explicitly send. Your friend chooses Receive into vault.

An unchecked identity is not a verified identity, even though encryption remains enabled.

Together, by invitation

Create a group

  1. In Private chats, choose Create group and name it.
  2. Open Members and settings → Invite friend.
  3. Invitees open the invitation and explicitly choose Join group.
  4. Use member settings for verification and admin roles. Send messages or select vault files with the attachment control.

Everyone should use 3.20+ for vault-file sharing. Members can keep or export their own received copies.

No internet route

Pair two nearby phones

  1. Connect both phones to the same Wi-Fi or a manually enabled hotspot.
  2. Open Nearby transfer → Send files, select your items, and prepare a pairing code.
  3. The other phone chooses Receive files and scans the QR or pastes the code.
  4. The recipient reviews the list and confirms. Keep both vaults open until verified receipt.

Treat a pairing code like an invitation for one intended receiver. Resume sharing uses a fresh code after locking.

Know what leaves

Export deliberately

  1. Select the file or folders you want to copy out.
  2. Choose File Unlock and read the plaintext warning.
  3. Pick a writable destination folder in Android's file picker.
  4. Review the completion report, including any partial failures or cleanup warnings.

The vault originals remain encrypted. Exported copies do not; other apps and backup services may retain them.

Privacy, with perspective

Protection you can
understand.

Full privacy & security details →
  1. ImportFiles stream into authenticated encrypted storage.
  2. UnlockYour password and device-backed key protection open the matching vault.
  3. ViewRequired data is decrypted for use, rather than exporting the whole library.
  4. Leave safelySafe Mode closes sensitive access and removes the task from Recents.

Imported files use authenticated AES-256-GCM encryption. Password-derived protection and Android Keystore guard the vault keys. Viewing decrypts the data needed for the current view, not the entire library into a public folder.

Safe Mode locks when you leave. Temporary Normal Mode deliberately keeps the vault unlocked in the background until screen-off restores Safe Mode.

The important boundaries

  • Root or malware: a compromised operating system may observe unlocked data or capture secrets.
  • Editing caches: some video editing and conversion use temporary app-private plaintext files. Cleanup runs on completion/failure and startup, but interruption or flash behavior can leave recoverable traces.
  • Exports and recipients: once plaintext or a received copy leaves your control, the app cannot recall it.
  • Recovery: there is no password-reset service. Uninstalling or clearing app data can destroy the installation's keys.

No forensic-proof, root-proof, or guaranteed-erasure claims. Android controls process lifetime and memory reclamation. Keep a verified backup and a strong password.

This website does not access your vault or run a chat relay. Feature searches stay in your browser. GitHub processes hosting/download requests under its own privacy policy.

Before you begin

Good questions.
Straight answers.

Need to report a problem?
Public issue tracker

How do I install and open the app?
  1. Download the APK from this page on a compatible Android device.
  2. If Android asks, allow this browser or file manager to install this app. Review the system prompts. You can revoke the install permission afterward; do not disable Play Protect.
  3. Open Clock. Draw a deliberate X in two long, crossing strokes over the launch clock face. Create and confirm an alphanumeric password of at least eight characters.
  4. Import a small test file first and make sure you can reopen it. Keep originals until you have verified your import and backup.

Android or your device administrator may restrict installation. Follow official platform guidance; a website cannot override those restrictions.

How do I return from the full clock mode?

On the normal launch clock, draw the two-stroke X. If you enabled Extreme Camouflage Mode, open its Clock tab and continuously hold the large digital time for four seconds, then enter your password. Successful authentication returns to the vault and disables that camouflage mode until you enable it again.

Leaving a password prompt or entering a wrong password does not disable camouflage.

Does unlocking decrypt all my files?

No. It makes the matching vault keys available so the app can read the data required for your current action. The library is not bulk-exported into a public folder. Decrypted content can exist in RAM while viewed; some video editing/conversion also requires temporary app-private plaintext files. See the security boundaries.

Can someone take the signing key from the download?

The APK and optional .idsig expose public verification data, not the private release signing key. The corresponding source download does not contain the signing keystore or its password.

Others may rebuild the open-source app with their own key, but those builds cannot normally replace an installed official version. A publisher's signing key is also different from each user's vault-encryption keys. The public signing-certificate fingerprint is in the release integrity details.

Is this a Play Store app?

This page distributes an independently signed APK, not a Google Play listing. Updates require downloading and installing a newer release over the current app.

Android developer-verification rules are evolving. Google's current guidance distinguishes the initial participating-store rollout from direct sideloading and describes an advanced flow for unregistered apps. Check the official Android guidance for your device and region. Hosting a download is not Google approval.

Does everything need the internet?

No. The encrypted library and clock work locally. Private chats use third-party encrypted relays while unlocked. Explicit public-link imports also use the internet. Offline Nearby sharing needs a compatible shared local network, but no chat identity or internet connection.

What happens if I forget my password?

There is no password-reset service that can recover your vault. Uninstalling, clearing app data, or losing the installation's Keystore key can make local data unrecoverable.

A separately created library backup can restore the backed-up library with its own backup password. It does not recover the original password or chat identity/history. Test your backup before relying on it.

Why does the app ask for these permissions?

Android's file picker grants access to the documents and folders you select. Network access supports optional chats and public-link imports; Nearby may need a local-network permission. The camera is optional for Nearby QR scanning, with pasted codes as an alternative. Notifications and exact-alarm access support alarms, timers, and playlist reminders.

The clock artwork does not request your location. See the full permission and data explanation.

Why does a photo or video preview fail?

A file may use an unsupported codec/container, have missing metadata, or be damaged. Android 8.0 has additional preview-resolution limits. A missing video thumbnail does not necessarily prevent an attempt to play it. Check a small, known-good file first and keep the original while investigating; errors do not mean the app silently repaired the file.

Why did an alarm, reminder, or transfer not finish?

Check notification and exact-alarm permissions for clock events. Android and manufacturer restrictions can affect scheduling; some reminders are explicitly approximate when exact-alarm access is unavailable.

For transfers, keep the vaults open, check the network and local permissions, and inspect the reported state before retrying. Relays are best-effort and Nearby can be blocked by router isolation. Sent, relay-accepted, and verified vault-saved are different states.

What should I know about group sharing?

Use version 3.20 or later on every recipient's device for vault-file sharing. Group files use relay delivery, not Nearby, and have a 100 MiB per-file limit. Receipt tracking waits for the original recipients' confirmed vault saves before automatic relay cleanup.

Members can retain or export copies. Removing a member does not erase those copies, and groups are not anonymous to their members. Missing receipts, offline users, and relay expiry can affect availability. Removing a member and cancelling a transfer can show a connection warning; Retry reconciles the remaining chats.

Can I read the source or report an issue privately?

The matching source, build instructions, and third-party source materials accompany each public APK release under AGPL-3.0. See licensing and source availability.

The public GitHub issue tracker accepts non-sensitive bug reports and source-availability requests. Reports and replies are publicly visible. Do not post vault files, passwords, private messages, or other people's personal information in public reports. No private support or password-recovery service is promised.

What changed in version 3.20?

Encrypted group conversations, invitations, member verification, admin controls, and vault-file sharing were added. Recipient-aware save receipts prevent the first recipient from causing early cleanup for everyone else. The existing vault theme and locking behavior are retained.

This release was exercised on emulators; compatibility across every manufacturer and device is not guaranteed.
